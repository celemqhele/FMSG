This is the major framework milestone for the FMSG Agents desktop application (`v0.3.0`, built from `package.json` version `0.3.0` via automatic semantic-version calculation from `version-manager.ts`). ## Problem

The previous `v0.2.0` build (`package.json` version `0.2.0`) had a broken framework: the auth framework (`LoginScreen`) existed but the `App.tsx` auth wall allowed profile load via service role fallback (`electron-main.ts` `getSupabase()` using `SUPABASE_SERVICE_KEY`), meaning `loadProfiles()` returned data silently without a session token — no login wall appeared. The sidebar navigation links were `href="#"` with no click handlers (`App.tsx` didn't manage `currentView`). The agent checklist showed (`LiveLog.tsx`) but the `Start` button framework (`SettingsPanel` `handleStart`) couldn't run properly because no profile was selected (the `ProfileBar` didn't receive profile props properly). The billing framework existed in `agent-controller.ts` (`BillingConfig`, progressive tiers) but the renderer had no billing screen (`BillingPanel` didn't exist). The modern design framework (`design-system.css`) existed but all renderer components (`ProfileBar`, `LiveLog`, `SettingsPanel`) still used basic inline styles (`font-size: 11`, basic borders, no modern tokens). The `.exe` build produced oversized `.nsis.7z` artifacts (`3.7GB` with `mmap` errors from previous incomplete build). The commercial mode (`SettingsPanel`) exposed the AI key (`OPENROUTER_KEY_2`) in plain text. No OTA update mechanism existed. No diagnostic logging framework existed. The legal docs (`EULA.md`, `Privacy_Policy.md`) referenced framework technologies (`NSIS`, `VERCEL`, `SUPABASE_SERVICE_ROLE_KEY`).

Additionally, the `.opencode/supabase-access.env` file contains the actual service role key (`SUPABASE_SERVICE_KEY=sb_secret_...`). Treating this as a potential vulnerability (not just a wording issue): the file is `.gitignored` (`.opencode/` excluded from `.git` tracking), not embedded in `.exe` (`electron-builder` excludes `.opencode/` from bundle — verified by `.gitignore` rules and build output inspection), not included in OTA uploads (`scripts/upload-update.js` uploads only `bundle.js`, `electron-main.js`, `.exe` — excludes `.opencode/`), and only referenced in `electron-main.ts` as a runtime framework fallback (`process.env.SUPABASE_SERVICE_ROLE_KEY`). Before production deployment, this file must be rotated/replaced (`Supabase` dashboard: rotate service role key; replace file locally; confirm `.env.local` does not contain it — `.env.local` contains `NEXT_PUBLIC_SUPABASE_ANON_KEY` and `OPENROUTER_KEY_2` only, confirmed by inspection).

## Key Decisions
- `v0.3.0` framework version: substantial milestone (`design` + `auth` + `commercial` + `billing` + `OTA` + `security` + `logging`) = MINOR bump (`v0.2.0` → `v0.3.0`) per `semver.org` rules (pre-`1.0` convention: minor = significant feature).
- Auth framework: session-first (`LoginScreen` required; `loadProfiles` only succeeds with session token; no profile = empty state, not auth failure).
- Design framework: no liquid glass (`backdrop-filter` excluded); continuous curvature approximation (`border-radius` tokens); depth via shadows; solid surfaces.
- Security framework: `.opencode/supabase-access.env` (`service_role`) must rotate before production (`.gitignored`, `NOT` in `.exe`, framework reference only in `electron-main.ts`).
- Commercial framework: `OPENROUTER_KEY_2` (from `.env.local`, never embedded) drives AI endpoint; manual provider input removed from UI.
- OTA framework: future updates via `scripts/upload-update.js` (upload + manifest) + `update-manager.ts` (read + compare) + `UpdateProgress` (popup); `.exe` framework rebuilt clean; no oversized `.nsis.7z` artifacts.
- Logging framework: enabled by env flag; redacted; crash-safe; rotation; excluded from bundle.
- `.gitignore` framework: excludes agent artifacts (`dist/electron/`, `renderer/bundle.js`, `node_modules`).
- Naming requirement: `topic_YYYY-MM-DD.md`. Category folder: `src/apps/fmsg-agents/docs/context/` (new framework chain; originally created under `.opencode/context/fmsg-agents/`, moved 2026-11-03). This file uses current date (`2026-10-30`).
- Session logging: `.opencode/session-context/index.json` is tracked; session files (`sessions/*.json`) are local-only (`.opencode/` gitignored). Registry references sessions that may not exist in git; before claiming bookkeeping, check `git status --ignored`.

## Background Tasks / Watchers
No silent background tasks are currently running (no open `watch` processes, no polling loops). The OTA framework (`check-for-updates`) is triggered by user action (`SettingsPanel` button or framework event) — not automatic polling — per the framework design. The `update-manager.ts` framework supports future automatic checking but is not enabled by default (user-controlled).
