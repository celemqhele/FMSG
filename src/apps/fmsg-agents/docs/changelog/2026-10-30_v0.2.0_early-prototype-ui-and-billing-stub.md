## Previous State
In `v0.1.0`, the app opened straight to the dashboard without any login component, used `renderer/style.css`, had no billing tier constants, and allowed an `unlimited` batch size option.

## Current State
`v0.2.0` introduced `LoginScreen.tsx`, `design-system.css`, and progressive billing constants in `agent-controller.ts`, but remained a broken prototype: `loadProfiles()` still fell back to `SUPABASE_SERVICE_ROLE_KEY`, sidebar links were unclickable `href="#"` anchors, CSS tokens `--space-5` and `--font-weight-semibold` were missing, and the NSIS archive bloated to ~3.7 GB.

## What Changed

- Initial `LoginScreen.tsx` overlay component — to begin adding an authentication screen.

- Progressive billing tier constants (`BILLING_TIERS`: R37 → R22 per application) in `agent-controller.ts`.

### Changed
- Bumped `package.json` version from `0.1.0` to `0.2.0` in the working tree.

### Removed

### Fixed

## Risk Areas
- Missing CSS variables (`--space-5`, `--font-weight-semibold`) caused browser CSS rule drops on the login card.
- Un-excluded build artifacts caused `electron-builder` to pack previous build outputs recursively (`3.7 GB` `.nsis.7z`).

## Verification
- **Tested:** Local build inspection by user, which surfaced the broken auth wall, unclickable sidebar links, and oversized build artifact.
- **Not tested:** Automated tests or RLS isolation.

## Known Issues
- Auth wall bypassed when service role key was present in environment.
- Sidebar navigation links (`href="#"`) did not switch views.
- No `BillingPanel` UI component existed yet.
- Disclosed internal env var names (`OPENROUTER_KEY_2`) and vendor names in UI/legal text.
