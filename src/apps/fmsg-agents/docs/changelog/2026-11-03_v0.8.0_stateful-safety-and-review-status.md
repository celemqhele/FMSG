# FMSG Agents v0.8.0 — Stateful Safety Release (Phase 1B)

Installer release that makes the Approve / Skip / Remove loop durable across restarts and fixes the two main-process defects deferred from `v0.7.1`. Unlike `v0.7.2`, this release changes the Electron main process, the preload IPC contract and the shared database schema, so it **cannot** be delivered as a renderer-only OTA bundle.

## Problem

`v0.7.2` made the review loop honest in the renderer, but the state had nowhere durable to live:

- `public.saved_jobs` had no status column. Review membership was inferred by substring-matching `match_summary` (`deriveJobStatus`), so an approval could not be represented, audited or synced to the website.
- The table had `SELECT`, `INSERT` and `DELETE` RLS policies from migration `005` but **no `UPDATE` policy**, so even a correct client could not persist a status change under RLS.
- Removing a record meant `DELETE`. There was no reversible archive, so an accidental removal was unrecoverable.
- The main process exposed only `saved-jobs-list` and `saved-jobs-delete`; the renderer had no channel for a status transition.
- The version chip could lag one release after an installer upgrade (`verifyStartupSlotHealth` only re-synced `active_slot_version` when `Slot-Active` existed).
- Installer-handoff OTA was blocked because GitHub-hosted `download_url` entries received Supabase credentials (presigned URLs reject a conflicting `Authorization` header) and every download had a hard 30-second timeout, far too short for a ~92 MB `.exe`.

## Fix

### Migration 039 (`P1B.1`)
`supabase/migrations/039_saved_jobs_review_status.sql`:

- `review_status text NOT NULL DEFAULT 'applied'` with a `CHECK` constraint (`applied`, `needs_review`, `approved`, `submitted`, `skipped`).
- `archived_at timestamptz` for reversible removal.
- Partial index `idx_saved_jobs_review_active (user_id, review_status, created_at DESC) WHERE archived_at IS NULL`.
- `FOR UPDATE` RLS policy scoped to `auth.uid() = user_id` with a matching `WITH CHECK`.
- `GRANT ALL` for `anon`, `authenticated`, `service_role` (Supabase no longer auto-grants new tables; included here for parity and safety).
- One-time backfill of legacy rows from the `match_summary` heuristic, restricted to `review_status = 'applied' AND archived_at IS NULL` so a re-run never overwrites an approval.

The migration is idempotent and documented with per-statement verification queries, a PostgREST schema-cache note, and a rollback block.

### IPC and preload contract (`P1B.2`)
- `saved-jobs-list` now selects `review_status` and `archived_at` and excludes archived rows server-side. If the migration has not been applied yet, the handler detects `42703` and transparently falls back to the legacy column set (`schema: 'legacy'`) so the app never breaks.
- New `saved-jobs-update-status` validates the status against the allowed set and scopes the update to `user_id`.
- New `saved-jobs-archive` sets or clears `archived_at` — never deletes.
- Preload exposes `updateSavedJobStatus(id, status, matchSummary?)` and `archiveSavedJob(id, archived)`; the old `deleteSavedJob` channel remains for compatibility but the renderer no longer uses it for destructive actions.
- `agent-controller.ts` writes `review_status` explicitly on insert: confirmed submissions become `applied`, everything prepared but unconfirmed becomes `needs_review`.

### Approve / submit / skip flow (`P1B.3`)
- Approve writes `approved`, appends an auditable “Approved in Review Queue on 2 Nov 2026.” note to `match_summary`, opens the employer posting and removes the item from the queue.
- `Mark Submitted` writes `submitted` from the application detail view.
- Skip writes `skipped` and archives the row; Undo restores `needs_review` and clears `archived_at`.
- The tracker distinguishes `Applied`, `Needs Review`, `Approved`, `Submitted` and `Skipped` with colour, text and a status dot.

### Confirmation and undo (`P1B.4`)
- Disconnect a saved job-board sign-in now requires typing the site name and explains exactly what stops working.
- Remove and Skip archive instead of deleting, with a 10-second Undo toast.
- Account deletion states that entering the emailed code deletes immediately.

### Applications actions and detail (`P1B.5`)
- Labelled `Actions` column with 32px controls, sortable headers, status filters, search-clear and a 40px-equivalent back control (breadcrumb).
- Detail view shows salary, match, recorded date, status, posting link/copy-link and a timeline.

### Profile data cleanup (`P1B.6`)
- Backed up all 30 `search_profiles` rows (`recycle_bin/backup_search_profiles_2026-11-03.json`) before writing a rollback snapshot.
- Stripped trailing numeric indexes from 7 profile names and inserted the missing comma in 8 location strings via the service key; verified 0 remaining suffixes and 0 remaining ungrammatical “X South Africa” strings.
- The renderer additionally normalises names and locations at display time, so future data never regresses the UI.

### Main-process fixes (`P1B.7`)
- `verifyStartupSlotHealth` now always sets `active_slot_version = APP_VERSION` and clears `backup_slot_version` in the installer-upgrade branch, whether or not `Slot-Active` exists.
- `downloadAndApplyVerifiedRelease` no longer sends Supabase credentials to external `download_url` hosts and uses a 15-minute timeout for external artifacts (2 minutes for bucket objects).
- `scripts/upload-update.js` gained `--installer-url` and `--dry-run` so signed installer manifests can point at GitHub Releases without a 92 MB bucket upload.

### Release (`P1B.8`)
- `npm run build:all` produced `FMSG Agents Setup 0.8.0.exe` (92,415,932 bytes) with `keytar` rebuilt for Electron 34.
- Packaged `app.asar` verified to contain `saved-jobs-update-status`, `saved-jobs-archive` and `0.8.0`.
- Previous installers moved to `recycle_bin/old_installers/`.

## Known release dependencies (must be resolved before distribution)

1. **Migration 039 has not been applied.** PostgREST answers `42703 column saved_jobs.review_status does not exist`, verified on 2026-11-03. DDL needs the Supabase SQL editor (or a Management API token that this workstation does not hold). Apply it statement-by-statement, then run the verification queries in the migration file. Until then the app keeps working via the local override store and the `legacy` fallback, but approvals only persist on this PC.
2. **Installer delivery.** `v0.8.0` changes main + preload + schema, so it must be installed (`FMSG Agents Setup 0.8.0.exe` / `/S /UPDATE`), not pushed as a renderer OTA. Installer-handoff OTA now works in code but still requires either a raised Supabase Storage limit or a GitHub Releases `--installer-url` (the fix ships in this build, so the next release can use it).
3. **Clean-VM install test** has not been performed in this session.

## Risk areas

- `saved-jobs-list` has two schemas; keep the fallback until every environment has Migration 039 applied, then it can be simplified.
- The local override store (`fmsg_agents_job_overrides_v1`) remains as an optimistic cache. It is never the source of truth once the migration is live, but it is not pruned automatically.
- `match_summary` grows by one short audit sentence per action (capped at 500 chars by the IPC handler).
