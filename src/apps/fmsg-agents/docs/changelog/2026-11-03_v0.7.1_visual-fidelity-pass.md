# v0.7.1 — Visual Fidelity Pass (Hierarchy, Hero, Empty States)

**Release date:** 2026-11-03
**Type:** patch (renderer-only — OTA eligible)
**Previous:** `v0.7.0`

---

## Summary

A screen-by-screen comparison of the shipped `v0.7.0` build against the 18
individual mockups (`docs/design/reference/`, sheet source) showed the visual
language was derived (palette, sidebar, cards, pills, ring) but the **type
hierarchy had collapsed** and three composites diverged. `v0.7.1` restores the
mockups' display scale without giving up the compact body sizing, rebuilds the
Home hero as a two-column banner, replaces the fake-loading-skeleton empty
states with a real empty-state component, and removes the duplicate primary CTA.

Measured before this release: mockup hero headline ≈36px / page title ≈28–30px
against our 18px / 17px, while body text was already at 85% of the mockup size.
Body was right; display type was half size, so every screen read flat.

---

## Added

- **`EmptyState` component** (`renderer/App.tsx`) with three shapes: default
  (icon + headline + body + primary action), `compact`, and `inline` for
  dashboard widgets. Styled by `.empty-state*` in `design-system.css`.
  - Applications: "No applications yet" with **Go to Run**.
  - Review Queue: "Review queue is all clear" with **Go to Run**.
  - Applications filtered-to-zero: "No matching applications" (no action).
  - Home "Last 7 days" / "Recent applications": inline variant, no action — the
    hero already owns the page's single primary CTA.

## Changed

- **Type hierarchy restored to the mockups' ratios:**
  | Token | v0.7.0 | v0.7.1 | Mockup |
  |---|---|---|---|
  | Hero headline | 18px | **26px** | ≈36px |
  | Screen title (`.billing-title`) | 17px | **22px** | ≈28–30px |
  | Card head (`.bento-card-head h3`) | 13.5px | **14.5px** | ≈15–16px |
  | Section title (`.billing-section-title`) | 12.5px | **13.5px** | ≈15px |
  | Onboarding title | 18px | **22px** | ≈34px |
  Body/secondary/labels/caption unchanged at 13 / 12 / 11.5 / 11px, so the
  compact scale and the 11px floor still hold.
- **Home hero rebuilt as two columns** (`.dashboard-hero-card` is now a grid:
  `minmax(0,1fr) 322px`). Left: eyebrow, 26px headline, active-profile line,
  `Start Applying` CTA. Right: three feature rows (Find relevant roles / Tailor
  with AI / Apply and track) with 30px indigo icon tiles — the mockup's
  composition instead of a centred block with a dead right half.
- **Quick action tiles are horizontal** (icon left, title over subtitle) via a
  2-column grid on the existing markup. Saves ~90px of height and matches the
  mockup tile shape.
- **Review Queue title** is "Review Queue" when the queue is empty, instead of
  "0 applications need your review".

## Removed

- **Duplicate primary CTA.** The sidebar footer no longer renders
  `Start Applying` at idle; it only appears while a run is active, labelled
  **Run Controls**. The hero owns the idle-state CTA (as in the mockup).

## Fixed

- **`Last 7 days` read as a loading skeleton.** At zero data it rendered seven
  empty bar boxes with a 2px blue baseline; it now shows an empty state.
- **Dashboard overflowed the 1360×860 viewport.** After the hero/empty-state
  work the bottom row was clipped (`Active profile` cut at the fold). The
  horizontal tiles plus inline empty states bring the whole dashboard back
  inside the viewport with no scroll.
- **Sidebar plan line wrapped** to two rows (`PAYG · Cap` / `R160`) next to the
  collapse button. Now `PAYG · R160 cap` on one ellipsised line.

## Verification

- `npx tsc -p tsconfig.json --noEmit` — clean
- `npx tsc -p tsconfig.main.json --noEmit` — clean
- `npm run build:renderer` — `renderer/bundle.js` 382.6kb
- Visual check on all seven nav screens at 1360×860 CSS (Windows 125% scaling,

  primary CTA, empty states render on Home / Applications / Review, 22px titles
  do not overflow any header row.

---

## Risk Areas

- `.billing-title` is shared by Applications, Review, Profiles, Billing and
  Settings; all five headers were re-checked at 22px for wrapping.
- `.dashboard-hero-card` is now `display: grid`; the `.dashboard-hero-glow`
  child stays `position: absolute` so it does not take a grid track.
- `EmptyState` is a new shared component — the `inline` variant assumes a
  fairly narrow card (~300–460px).

## Deployment Notes

- **Renderer-only change** (no main-process, preload or native-dependency
  changes), so this release is eligible for renderer-only OTA. Unlike `v0.7.0`
  it does **not** need `--requires-installer`.
- The titlebar/Settings version chip reads the active renderer slot version, so
  it shows `v0.7.0` until the new slot is installed or the OTA is applied.
