# FMSG Agents v0.10.0 — Live Browser View, Identity-Led Profile Cards & Full-Width Update Screen

Three-workstream feature update delivered under the three-agent engineering governance system (`TASK-20261103-001/002/003/004`, blueprints `BLUEPRINT-20261103-001/002/003`, all reviewed and approved by Argon). The Run screen gains a live CDP-screencast view of the automation browser so users watch Chrome fill applications in real time instead of taking screenshots; the Profiles screen is rebuilt as centred, identity-led SaaS cards with a green Active Profile pill; and the feature-update screen becomes a full-width page instead of a small card with a nested scrollbar. Changes include the Electron main process and the preload IPC contract, so this release is **installer-handoff** (`requires_installer: true`), not a renderer-only swap.

## Problem

1. **Start Apply interrupted the workflow.** Pressing Start Apply launched a visible Chrome window outside the app, so users could not observe the agent's progress without taking screenshots (`TASK-20261103-003`).
2. **The profile cards were dense and identity-poor.** Career roles, locations, company types and salary competed with the profile owner's identity; small left-aligned avatars and disconnected Select/Active chips made the grid hard to scan (`TASK-20261103-002`, founder clarification authoritative over the reference image).
3. **The update container was cramped.** The "New Feature Update Available" screen rendered in a 430px centred card, and long changelogs developed their own vertical scrollbar inside a 140px box (`TASK-20261103-001`).

## Fix

### Live browser streaming (`TASK-20261103-003`)

- `AgentRunner` opens a page-level CDP session and runs `Page.startScreencast` (JPEG q55, 960×540, `everyNthFrame: 2`), emitting a new `browser-frame` agent event at ≤10 fps through the existing `agent-event` IPC channel — **no new IPC surface, no preload change, no new dependency**.
- Every frame is ACKed (`Page.screencastFrameAck`) **before** any throttle/drop decision, so the stream cannot stall.
- The Run screen preview panel renders the newest frame (single frame in state, no history) with a pulsing LIVE indicator, a current-pipeline-step overlay, and Pause/Resume feed; the milestone-still path remains as fallback (accelerated to 1 per 2s when screencast is unavailable).
- Automation-window management: `Target.getTargets` → `Browser.getWindowForTarget` → `Browser.setWindowBounds` (`windowState: 'normal'`, never minimized — minimized windows throttle rendering) places Chrome behind the app; the app window is re-focused after launch so it stays the user's primary surface.
- **Security:** the preview is view-only (no in-app navigation controls — user navigation would race the agent); it renders the actual automation surface, so session isolation is preserved by construction; frames are never written to disk and `logger.ts` redacts `data:image/…;base64,…` strings and `dataUrl|frame|screencastFrame` keys.

### "Open in Chrome" control (`TASK-20261103-004`, corrective — closes escalation `E-003-A`)

- The preview footer carries an **Open in Chrome** button that raises the automation Chrome window on demand (hidden until a run starts; exactly one IPC call per click; no navigation; boolean result only).
- Mechanism: `AgentRunner.focusAutomationBrowser()` reuses the retained browser-level CDP session — `Target.getTargets` → `Browser.getWindowForTarget` → `Browser.setWindowBounds { windowState: 'normal' }` (only when not already normal) → `Target.activateTarget`. One `ipcMain.handle('agent-focus-browser')` guarded by `agentRunner.isRunning()`, one preload method `focusAutomationBrowser()`. Failures surface as an informational toast.

### Centred SaaS profile cards (`TASK-20261103-002`)

- Visual hierarchy **avatar → name → CV status → action controls**: 76px circular initials avatar centred at the top, profile name, subtle CV status ("CV attached" / "No CV on file"), and a divider-separated action footer.
- Selected card: green **Active Profile** pill. Other cards: a single **Select** control. No contradictory or duplicate selection states (the reference image's dual chips were intentionally not copied — the written clarification governs).
- Career metadata (job titles, industry, location, expected salary) removed from the card presentation only; underlying profile data untouched.
- The Run-page `ProfilePicker` is identity-led: avatar + presence dot + name trigger; dropdown rows carry avatar + two-line "name / title · location" body. The `create-new` card is restyled to match (dashed border, `+` avatar).
- Two pre-existing picker defects fixed as part of the alignment: the menu opened rightward off-screen (re-anchored to the trigger's right edge) and rows stacked vertically (direction pinned to `row`).

### Full-width feature-update screen (`TASK-20261103-001`)

- `UpdateProgress.tsx` renders every phase inside `.update-screen-page` (1080px page, page-level scrolling via the existing `.auth-viewport`), with `.is-hero` (checking/downloading/installing — centred 560px splash) and `.is-page` (optional-feature prompt — document page) modifiers.
- The changelog is flowing content (`.update-changelog` / `.update-changelog-list`, two columns down to 720px): the `maxHeight: 140px` / `overflowY: auto` scrollbox is deleted; a 60-bullet changelog grows the page and scrolls at page level (`innerScrollRegions = 0` measured).
- `mode="modal"` renders a bordered dialog surface (960px, `.modal-backdrop.update-modal-backdrop` with `align-items: safe center`) — the compound selector is required because `.modal-backdrop` is declared twice in `design-system.css` and the later rule wins on equal specificity.
- All four phases preserve copy, buttons, deferred-batch logic and progress ARIA semantics (probe-verified).

## Risk areas

- **Minimized-window throttling** can stall the screencast — the window is therefore held in `normal` state behind the app, never minimized; the conditional `setWindowBounds` in the focus control will not shrink a maximized window.
- **Installer-handoff distribution** requires the installer upload to the `agent-updates` bucket to succeed; if the storage size limit rejects it, the manifest must instead reference an external HTTPS `download_url` (GitHub Releases) — see Delivery status.
- The unused `mode="wizard"` on the update screen is accepted-but-untested (no mount site uses it).

## Delivery status

**Delivered by silent installer on the founder's machine** (`FMSG Agents Setup 0.10.0.exe /S /UPDATE`, `2026-11-03T18:31:00+02:00`): `install-state.json` now reads `installed_version 0.10.0` / `active_slot_version 0.10.0`.

- **No OTA manifest was published for this release.** The installer-handoff manifest requires the ~92 MB installer to be reachable, and the `agent-updates` bucket rejects it with `413 EntityTooLarge` (Supabase per-object size limit — the same blocker that prevented installer-handoff for `v0.8.0`). A renderer-only manifest was deliberately **not** published: this release changes the main process and preload IPC contract, and swapping only the renderer would pair the new UI with an old main process that never emits `browser-frame` events and lacks the `agent-focus-browser` channel.
- The stable/beta manifests remain at `0.9.0`; the founder's app at `0.10.0` therefore reports "Up to date" and the version chip reads `v0.10.0`.
- **To restore OTA installer-handoff for future releases**, one of the following is required (founder decision): (1) host installers externally and publish with `--installer-url` (GitHub Releases — needs a `gh` CLI/token on this machine), or (2) raise the Supabase storage per-object limit (plan change).
- The plain-text OTA changelog (`2026-11-03_v0.10.0_embedded-browser-profile-cards-full-width-update.ota.txt`) is ready for reuse the moment a distribution channel exists.
