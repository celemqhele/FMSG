# v0.7.0 - Mockup Redesign, Local Secret Vault & Application Bundles

**Released:** 2026-11-03
**Type:** minor
**Range:** `v0.6.0..v0.7.0`

---

## Summary

Replaces the `v0.5.1` cosmic/dock shell with the mockup sheet layout: a frameless
dark window with a custom title bar and a permanent left sidebar, plus every
screen on the sheet (Home dashboard, Run setup, Live Run, Needs You, Applications
tracker, Detail & replay, Review queue, Profiles, Rules & Answer Bank, Billing,
Settings, onboarding wizard, empty/error states). Adds the local Windows
Credential Manager secret vault (domain-locked `fill_secret`), a persistent Answer
Bank and screening rules, and FMSG Agents-only application bundles with a cost cap
that starts at R0.

The FMSG website (pricing, searches, CV/PF features) is untouched: the website
searches, the agent applies. Searches are included in every agent application.

## Added

### UI shell (mockup parity)
- `custom-titlebar`: 36px frameless dark bar with brand mark, live run status pill,
  Tour and Notifications buttons, and working minimise / maximise / close.
  `electron-main.ts` now creates the window with `frame: false` and
  `backgroundColor: '#040613'`.
- `app-sidebar`: 184px expanded / 56px collapsed, active-rail indicator, live
  badges, `Start Applying` action, user block, collapse toggle. Replaces the
  bottom dock entirely (the dock markup and its CSS are gone).
- Home dashboard: hero CTA, four quick-action tiles, real 7-day activity bars
  computed from stored application records, recent applications, usage ring.
- Run setup modal: profile picker, batch presets + custom target, autonomy modes,
  daily cap, live estimated cost at the active per-application rate.
- Live Run: determinate progress bar, six-stage vertical pipeline, current-job
  spotlight with match badge, scrolling activity stream, dark screenshot monitor.
- Needs You modal: SVG countdown ring (10:00) that expires strictly into **skip**
  (never auto-submit), optional "save this login" path into the local vault.
- Applications tracker with search + status filters, application detail with
  timeline/replay and stored spec, Review queue, Profiles grid, Rules & Answer
  Bank, Billing, Settings, Account, empty/error states, 4-step onboarding wizard.
- Notifications popover (kept although it is not on the sheet), email-verification
  banner and 6-digit verification modal.

### Local secret vault (`secret-vault.ts`, new)
- `saveSiteSecret` / `deleteSiteSecret` / `listSiteSecretsMeta`: metadata in
  `%LOCALAPPDATA%\fmsg-agents\security\site-secrets-meta.json` (mode 0600), value
  in Windows Credential Manager via `keytar`, AES-256-GCM fallback bound to a
  local wrapping key when `keytar` is unavailable.
- Key names are normalised (`linkedin` -> `LINKEDIN_PASSWORD`), one per site, and
  each name is locked to exactly one approved domain.
- `fillSecretOnVerifiedDomain(page, keyName)` re-checks the live Playwright
  `page.url()` hostname (`host === allowed || host.endsWith('.' + allowed)`)
  before typing, blurs `input[type="password"]` before any screenshot, and never
  returns the password to the caller, renderer, model, or logs.

### Rules, Answer Bank & preferences
- `loadScreeningRules` / `saveScreeningRules`: min salary, locations, must-have
  keywords, excluded companies, and reusable answers with `askEachTime`.
- `loadAgentPrefs` / `saveAgentPrefs`: `costCap` (defaults to **0**), billing mode,
  bundle tier, autonomy mode, onboarding flag, successful payment count.
- IPC: `secrets-list`, `secrets-save`, `secrets-delete`, `rules-get`, `rules-save`,
  `agent-prefs-get`, `agent-prefs-save`, `saved-jobs-list`, `saved-jobs-delete`,
  `account-send-delete-code`, `account-confirm-delete`, `pause-agent`,
  `resume-agent`, `emergency-stop-agent`, `window-minimize`, `window-maximize`,
  `window-close`.

### Billing (FMSG Agents only)
- `/api/agent/billing/plans` now serves the agent catalogue: R40 pay-as-you-go
  (charge thresholds R40 -> R100 -> R250 -> R500), 5-application welcome bonus,
  default cost cap R0, and four monthly bundles -
  Starter 10 x R349 (R35/app), Lite 25 x R749 (R30/app),
  Standard 60 x R1,499 (R25/app), Power 150 x R3,299 (R22/app).
- `/api/agent/billing/checkout` and `/verify` accept the four bundle names with
  their own prices, so a desktop purchase can never be charged website pricing.

## Changed

- `design-system.css`: mockup palette (`#040613` / `#0B0E1F` / `#0E111A` /
  `#203EEA` / glow `#5028BF`) and a fixed px type scale (11.5 / 12 / 13 / 14 / 16 /
  18 / 20), 11px hard minimum. All new tokens are px, not rem, so Windows text
  scaling cannot inflate the layout.
- `agent-controller.ts`:
  - `pause()` / `resume()` / `waitIfPaused()`; the run parks between postings and
    resumes exactly where it stopped.
  - Sign-in walls first try the saved vault entry for the live host (`fill_secret`)
    and only then ask the user; the attention event carries `secretKeyName`,
    `allowedDomain`, and `countdownSeconds`.
  - Form answers now consult the Answer Bank before giving up on a field.
  - Pay-as-you-go rate is R40 per application with thresholds 40/100/250/500
    (replaces the old 3.7%-style tier ladder); bundle rates are R35/R30/R25/R22.
- `App.tsx` rewritten around the sidebar shell; `ViewType` is now
  `home | run | applications | review | profiles | billing | settings | account`.
- Cost cap initialises to **R0** and a run started at R0 sends the user to Billing
  with an explicit consent prompt instead of charging silently.
- Version strings are no longer hardcoded in the renderer; they come from
  `get-startup-status` / `get-update-settings`.

## Infrastructure Changes

- IPC contract additions: `pause-agent`, `resume-agent`, `emergency-stop-agent`,
  `window-*`, `secrets-*`, `rules-*`, `agent-prefs-*`, `saved-jobs-*`,
  `account-send-delete-code`, `account-confirm-delete`.
- New on-disk state (per-user, local only):
  `%LOCALAPPDATA%\fmsg-agents\security\site-secrets-meta.json`,
  `vault-wrap.key`, `user-data\rules-answer-bank.json`,
  `user-data\agent-billing-prefs.json`.
- No Supabase migration in this release. `saved_jobs` is read/written through the
  authenticated anon client under existing RLS.
- OTA: **`0.7.0` is installer-only.** No OTA manifest was published for this
  release, and `manifest.stable.sig.json` / `manifest.beta.sig.json` were left
  pointing at `0.6.0`. Reason: this release changes the Electron main process,
  the preload IPC contract and bundles a native module (`keytar`), so it cannot be
  delivered as a renderer-only bundle swap — an old main process would answer none
  of the new `window-*`, `pause-agent`, `secrets-*`, `rules-*`, `agent-prefs-*`,
  `saved-jobs-*` channels. The installer-handoff path
  (`requires_installer: true`, `installer/installer.nsh` runs it as `/S /UPDATE`)
  is implemented and now supported by `scripts/upload-update.js
  --requires-installer`, but the 92 MB `FMSG Agents Setup 0.7.0.exe` is rejected by
  the project's storage file size limit (`HTTP 413 EntityTooLarge`), so it cannot be
  uploaded until that limit is raised in Supabase.
- Consequence for anyone on the renderer-only `0.6.0` slot: install
  `dist/electron/FMSG Agents Setup 0.7.0.exe` once. From then on renderer-only
  releases can still go out over OTA.

## Risk Areas

- `frame: false` means the renderer owns window chrome; if the title bar fails to
  render, the window cannot be dragged or closed. The bar is rendered on every
  screen including boot, login, blocked, and modal states.
- `keytar` is a native module. If it fails to load, the AES-256-GCM fallback keeps
  the vault working, but the password then lives in the local encrypted file
  instead of the OS credential store; the log records which storage was used.
- Countdown expiry and run stop both resolve attention as `skip`. Sleep, Stop, and
  Emergency Stop therefore can never submit an application.
- **Discovery, 2026-11-03:** the machine this was built on reports
  `installed_version: 0.5.0`, `active_slot_version: 0.6.0` in
  `%LOCALAPPDATA%\fmsg-agents\updates\install-state.json`. Every release so far was
  published as a renderer-only bundle swap, so the Electron main process on disk is
  still the `0.5.0` installer's while the renderer claims `0.6.0`. Anything added to
  the main process since `0.5.0` (the live agent engine, Paystack IPC, and now the
  whole `0.7.0` main/IPC surface) has never actually run in the installed app.
  Until an installer-based update path exists, treat `active_slot_version` as the
  renderer version only and never as the version of the running main process.
- Bundle checkout reuses the website Paystack flow; the plan whitelist is what
  separates the two price lists. A plan name that is not in `PURCHASABLE` is
  rejected server-side.
