# FMSG Agents v0.9.0 — Design System, Structure & Responsive (Phase 2)

Renderer-only release that enforces the design system the audit said existed on paper but not in practice, extracts the largest views out of `App.tsx`, makes the Applications tracker scale to real datasets, and completes the responsive pass. It changes no main-process, preload or database code, so it is OTA-eligible.

## Problem

The audit's cross-application consistency section measured the gap directly: “the product has **tokens** but not a **system**”.

- **18 font sizes** in a 7-token scale, with metadata at 10.5px and a hard 11px floor (`GS-04`).
- **22+ border radii**; buttons alone used eight different values (`GS-05`).
- **18 layout `!important` declarations**, including a legacy override layer that existed only to repaint the light browser chrome (`GS-13`, `GS-14`).
- **Two content widths** — 1,040px on Billing/Settings and ~1,090px on Home/Applications — so navigating made the page jump (`GS-02`).
- **One breakpoint** for a 960–1920 range, leaving the sidebar at 184px even at 960 (`GS-11`, `RP-03`).
- **No pagination, export, sort or labelled action column** in the only table (`AP-01`).
- `App.tsx` held every view inline, so a design change required editing a 3,000-line file (`P2.2`).

## Fix

### Tokens and CSS (`P2.1`)
- Type scale collapsed to **7 sizes**: 12 / 13 / 14 / 16 / 18 / 22 / 26px. Every literal and inline `fontSize` was mapped onto it (no sub-12px text remains).
- Radius families collapsed to **4**: 6px controls, 10px cards/nav, 14px modals/hero, 999px pills (plus 50% circles).
- Radius tokens now resolve to those families (`--radius-sm/md/lg/xl/2xl/full`).
- **0 layout `!important`.** The dark browser chrome is now the actual implementation, so the `!important` override layer was deleted rather than restated; the remaining `!important`s are the two intentional `prefers-reduced-motion` declarations.
- One content width (`1200px`) for both `.billing-panel` and `.dashboard-home`, removing the navigation width jump (`GS-02`).
- `ui:shots` now **fails fast when `bundle.js` is older than the CSS** — the injected `<style>` wins over the `<link>`, which had been producing false visual measurements.

### Structure and primitives (`P2.2`)
- New `renderer/components/ui/primitives.tsx`: `Spinner`, `StatusPill`, `EmptyState`, `PageHeader`, `TableSkeleton`.
- Extracted `renderer/views/HomeView.tsx`, `views/ApplicationsView.tsx`, `views/ReviewView.tsx` with identical behaviour; `App.tsx` keeps the shell, routing, session state and modals. `Profiles`, `Onboarding` and `Account` remain inline for a later pass.

### Navigation, Settings, Profiles, Onboarding (`P2.3`–`P2.6`)
- Account is a first-class route with identity, plan, spend cap and security summary.
- Settings uses a section index, an equal-width vault grid, one-line update controls and a Danger Zone.
- Profiles and Rules are separated by tab with their own H1/subtitle; profile cards show salary and CV status; answers are editable in place; the salary rule has a numeric input beside the slider.
- Onboarding uses custom SVG icons (no emoji), explains the allowance/cap and “Approve each” in plain English, labels each step and offers **Skip tour**.

### Tables (`P2.7`)
- Sortable columns with direction indicators, status filters, search with a clear control, a labelled **Actions** column, pagination (25/50/100) and **CSV export** (UTF-8 BOM for Excel).
- Application detail keeps the breadcrumb, facts grid, timeline and copy/open actions.

### Responsive (`P2.10`)
- At ≤1100px the sidebar collapses to a 64px icon rail, and workspace modals re-centre on that rail.
- Breakpoint coverage verified at 960×640, 1280×720, 1360×860 and 1920×1080: no clipping, no horizontal overflow, Run Setup operable, sign-up fits.

- `npm run lint:content`: 0 violations across 15 renderer files.
- `npm run ui:a11y`: 0 violations (all impacts) across 10 screens; 10/10 focus rings.

- `npm run test:main`: 3/3.
- `npm run ui:shots -- --size 960,1280,1360,1920`: 13 screens × 4 viewports; 0 tiny text, 0 clipped, 0 horizontal overflow.

## Risk areas

- The type-scale collapse changes every screen’s metrics; the screenshot baseline under `tests/ui/baseline-v0.7.1/` is the pre-change reference, and `tests/ui/shots/` holds the current capture.
- `App.tsx` still owns `ProfilesAndRulesView`, `OnboardingWizardModal` and `AccountView`; extracting them is a mechanical follow-up.
- The 64px icon rail below 1100px hides nav labels; tooltips come from each item’s `title` attribute and the accessible name is preserved.
