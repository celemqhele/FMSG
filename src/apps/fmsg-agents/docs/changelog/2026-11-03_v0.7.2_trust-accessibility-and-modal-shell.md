# FMSG Agents v0.7.2 — Trust, Accessibility & Modal Shell (Phase 1A)

Renderer-only trust release that closes the Phase 1A slice of the independent UI/UX audit (`docs/audits/2026-11-03_fmsg-agents-ui-ux-audit_v0.7.1.md`). No Electron main-process, preload, database or installer change: every finding addressed here lives in `renderer/**`, the bundled legal documents, or build configuration, so the release is OTA-eligible.

## Problem

The audit scored the product 5.0/10 despite a strong visual identity, because the visible failures were semantic:

- **The primary action lied.** “Approve & Open” only opened the employer site — it never changed the record, so the Review Queue never emptied (`RV-01`).
- **Three destructive actions had no protection or undo** — Remove application, Skip review item, Forget credential (`AP-05`, `RV-03`, `ST-03`, `DL-01`).
- **Keyboard focus was invisible app-wide** (1px near-black default outline) and `--text-muted #64748b` measured 3.96:1 (`GS-01`, `GS-03`).
- **Run Setup was unusable at the app’s own minimum window** — 810px tall inside a 604px viewport, title and close button above `y = 0` (`RS-01`, `RP-01`).
- **Internal engineering detail shipped as customer copy** — `LINKEDIN_PASSWORD`, `fill_secret(name)`, “Windows Credential Manager”, “Fallback PAYG rate”, “Grace protection”, `dev_fd813828a7f8…`.
- **Legal documents were a 72-dash ASCII wall stamped `VERSION 0.6.0`** inside a `0.7.1` app (`ST-11`, `ST-12`).
- **Data truth contradicted itself** — “100% used” beside “6 / 5”, “Active profile 1”, duplicate weekday letters on the 7-day chart, three date/currency/location formats (`HM-01`, `HM-02`, `HM-04`, `AP-03`, `CT-01`, `CT-02`, `CT-05`).
- **Billing read like a pricing memo** with four competing primary CTAs and “Default R0” above “R160 max” (`BL-01`, `BL-03`, `BL-04`).

## Fix

### Formatting and data truth (`P1A.1`)
- New `renderer/lib/format.ts`: `formatDateZA` (`2 Nov 2026`), `formatDateTimeZA` (`3 Nov 2026, 10:30`), `formatZar` (`R1 499`, `R40 per application`), `formatLocationZA` (`Gauteng, South Africa`), `formatProfileName` (strips trailing array indices) and `computeAllowanceUsage`.
- Usage now renders `5 / 5 · +1 extra` with an amber ring and an explicit overage sentence instead of `100%` beside `6 / 5`.
- Home shows the active profile’s **name** (or “None”) instead of `1`.
- The 7-day chart labels each bar with its weekday, date (`28 Oct`) and count, and keeps the value on the bar.

### Internal identifier purge (`P1A.2`)
- Vault copy is now “Connected Job Accounts… encrypted and stored strictly on this computer”, with `Connected` / `Not connected` status and no env-var names, `fill_secret()` reference, OS credential-store name, or device ID.
- Installation identity is hidden behind a **Technical Details** disclosure and described as “Verified hardware-independent key stored securely on this PC”.
- Toasts say “Saved LinkedIn sign-in securely on this device” rather than naming a secret key.

### Billing clarity (`P1A.3`)
- Single canonical plan set (`Starter`, `Lite`, `Standard`, `Power`), one **Recommended** badge on Standard, and only Standard renders a primary CTA — the other three are secondary.
- “Default R0” contradiction removed: the cap card states the current cap, what it allows per month, and pauses automatically when reached.
- The threshold/stage/grace memo is replaced by plain-English plan benefits; welcome bonus has an explicit used/remaining state; all money uses `formatZar`.
- Added the billing backoffice surface: payment method, next renewal, spend forecast and a receipts list.

### Legal bundle & rendering (`P1A.4`)
- `legal/*.md` is bundled into the renderer (`--loader:.md=text`) and rendered through `renderer/lib/legal.tsx` with headings, sub-headings, paragraphs, lists and dividers — no ASCII rule walls.
- The document header version is synchronised to the running app version, and all three documents were bumped to `0.7.2`.
- The legal modal’s close action is secondary (never styled as the primary CTA) and the reader can copy the text.

### Titles, navigation and layout (`P1A.5`)
- Every route now has one stable noun H1 plus a one-line subtitle: Home, Run, Applications, Review Queue, Search Profiles / Rules & Answer Bank, Billing, Settings, Account.
- Review Queue title no longer mutates into a sentence; the count is a pill.
- Run gained a page header, and the active-profile picker no longer truncates the profile name at default size.
- **Account** is a first-class sidebar item with active state; sign-out is neutral (`btn-danger-outline`) rather than a primary danger button.
- Only one version string remains, in the titlebar.

### Accessibility baseline (`P1A.6`)
- Global `:focus-visible` → `2px solid #93c5fd` with offset; tab walk now reports 10/10 visible rings.
- `--text-muted` and every hardcoded `#64748b` text colour raised to `#94a3b8` (7.35:1 on cards); link colour raised to `#93c5fd`.
- Minimum text size is **12px** app-wide (90 → 0 sub-12px declarations).
- Checkboxes are styled; inputs have accessible labels; validation errors are `aria-describedby`-linked; sign-up validates every field at once with a summary.
- `axe-core` reports **0 critical, 0 serious, 0 moderate, 0 minor** across login, sign-up, home, run setup modal, run, applications, review, profiles, billing and settings.

### Modal shell and minimum window (`P1A.7`)
- Shared modal shell (`.shared-modal-shell`, `.modal-shell-header/body/footer`) with `max-height: calc(100vh - 72px)`, internal scroll, sticky footer and a 28px close button with an Esc hint.
- `DialogSystem` modals are pinned below the 36px frameless titlebar, trap focus, restore focus on close, and support Esc.
- Workspace modals centre in the content area (`left: 184px`, `56px` when collapsed) instead of under the sidebar.
- Run Setup at 960×640: geometry now `top 54 / bottom 622 / height 568` with the close button reachable (previously `top -86 / bottom 762`, unreachable). Sign-up card fits at 960×640, 1280×720, 1360×860 and 1920×1080.

### Notifications (`P1A.8`)
- Removed the seeded “Welcome to FMSG Agents v0.7.0” string. A one-time, version-aware welcome notification is stored per installed version (`fmsg_welcome_seen_v{version}`) and describes user actions, not internal features.
- Opening the panel marks everything read (badge clears), offers **Clear all**, and shows an “You’re all caught up” empty state.

### Loading, disabled and success states (`P1A.9`)
- Async buttons render an inline spinner with a verb-ing label (login, sign-up, reset link, update check, secret save, checkout, delete account).
- The tracker shows a shimmer skeleton while loading instead of a zero-data empty state.
- Saving the spend cap shows a persistent `Saved at HH:mm` marker; saving rules reports success.
- Login errors carry an inline “Forgot your password? Reset it here →” recovery action.

## Verification performed

- `npx tsc -p tsconfig.json --noEmit` and `npx tsc -p tsconfig.main.json --noEmit`: clean.
- `npm run build:code`: `renderer/bundle.js` 447.2kb.
- `npm run ui:flows` (**new**): **22/22** behavioural checks pass — Approve clears the queue while keeping the record, Skip/Remove archive with a working Undo, sorting/search-clear work, legal rendering shows 8 headings at `VERSION 0.7.2` with no raw dash walls, and notifications never show a stale version.
- `npm run ui:a11y`: 0 violations (all impacts) across 10 screens; 10/10 visible focus rings.
- `npm run lint:content`: 0 violations.
- `npm run lint:tokens`: `--text-muted` 7.35:1, 0 sub-12px declarations.
- `npm run ui:shots -- --size 960,1280,1360,1920`: 13 screens × 4 viewports captured; 0 tiny-text nodes, 0 clipped nodes, 0 horizontal overflow, sign-up fits at every size, Run Setup operable at every size.

## Delivery status

Built and verified locally as **`0.7.2`**. The OTA upload to the `agent-updates` bucket is intentionally **not** performed in this changeset — publishing a release is a distribution decision — but the release is renderer-only, so `node scripts/upload-update.js --version 0.7.2 --min-supported 0.7.1 --type security --changelog-file <ota.txt>` is the remaining step once approved.

## Risk areas

- **Review/Applications status is persisted locally** (`fmsg_agents_job_overrides_v1` in `localStorage`) until Migration 039 and the `saved-jobs-update-status` IPC channel ship in `v0.8.0`. The renderer already calls that channel when present, so the swap is additive.
- `renderer/bundle.js` inlines `design-system.css` at build time, and the injected `<style>` wins over the `<link>`. The screenshot harness now **fails fast** when the bundle is older than the CSS, to prevent false visual measurements.
- Auth inputs moved from 50px to 40px (32–34px at compact heights) to match the design-standard control scale; any future screen assuming 50px auth inputs should use the tokenised heights.
