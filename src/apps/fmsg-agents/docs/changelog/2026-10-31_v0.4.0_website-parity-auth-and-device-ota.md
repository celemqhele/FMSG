## Previous State
In `v0.3.0`, logging in from the packaged `.exe` failed immediately with `"supabaseKey is required"` (and once given a key, threw `"Node.js detected but native WebSocket not found"` inside Electron 34's Node 20.19.1 runtime). The login card was cramped due to missing CSS variables, native `alert()` dialogs were used, and updates were unsigned.

## Current State
In `v0.4.0`, all `SUPABASE_SERVICE_ROLE_KEY` references are removed from client code in favor of `config.ts` (`SUPABASE_URL` + public `SUPABASE_ANON_KEY` with startup JWT role validation). `session-manager.ts` provides a custom `DesktopRealtimeWebSocket` transport for Electron 34, full login/signup/forgot-password/6-digit verification parity with the website, OS keyring + DPAPI session persistence, and RLS-enforced `search_profiles` loading. However, the dashboard/agent runner and billing panel remained prototypes, and the `v0.4.0` OTA swap did not yet download the remote bundle files from Supabase Storage before swapping slots (fixed in `v0.5.0`).

## What Changed

### Added
- `src/apps/fmsg-agents/config.ts` — Bundled public `SUPABASE_URL`, `SUPABASE_ANON_KEY` (`role: "anon"`), `RELEASE_PUBLIC_KEYS_PEM`, and `validateStartupConfig()`.
- `src/apps/fmsg-agents/session-manager.ts` — Website-parity auth flows, `DesktopRealtimeWebSocket` polyfill for Electron 34 (Node 20.19.1), `instrumentedSupabaseFetch`, `keytar` + DPAPI session persistence, and RLS profile loading.
- `src/apps/fmsg-agents/device-key.ts` — Device-bound `Ed25519` + `RSA-OAEP-SHA256` keypair management.
- `src/apps/fmsg-agents/browser-resolver.ts` — System Chrome / Edge / Chromium path resolution for visible browser automation.
- `src/apps/fmsg-agents/renderer/components/DialogSystem.tsx` — Accessible in-app modal, toast, and legal document viewer replacing all `alert`/`confirm`/`prompt` calls.
- `src/apps/fmsg-agents/installer/installer.nsh`, `installerHeader.bmp`, `installerSidebar.bmp`, `icon.ico`, `legal/LICENSE.txt` — Custom branded per-user NSIS installer.
- `src/app/api/agent/updates/check/route.ts` and `supabase/migrations/037_agent_devices_and_updates_policies.sql` — Device update check route and `agent_devices` table.

### Changed

## Risk Areas
- `v0.4.0`'s `applySignedBundleUpdate` checked manifest signatures and swapped slots, but did not yet download the remote `v0.x.y/renderer/bundle.js` bytes from Supabase Storage before swapping (fixed in `v0.5.0`).
- `device-key.ts` in `v0.4.0` derived its local wrapping key from `MachineGuid` + OS username (replaced with zero-PII random key in OS Protected Storage in `v0.5.0`).
- Agent execution and billing UI were still prototypes.
